## Display scaling (100 / 125 / 150 %)
- The Editor is a CSS grid with rem-based minimum widths.
- Below 1100 CSS px, which is 150 % on a 1360-wide window, the inspector moves under the preview.
- Below 760 px everything stacks.
- CI captures the Editor at 100 %, 125 % and 150 % (`6-editor-100pct.png`, `6-editor-125pct.png`, `6-editor-150pct.png`) on the `ci-screenshots` branch.

## Rendering
**Covered by tests:**
- every layout × template with no guide pixels;
- every style with a facecam, without one, and with overlay rules;
- speed ramps, freezes and appended clips with exact durations;
- text, stickers, colour, rotate and transitions at pixel level;
- preview equals export;
- audio keyframes;
- loudness at −14 LUFS (existing).

**GPU encoders:** these fall back to libx264 when the GPU encoder fails (existing).

## Security
- **Token on every route:** proved by a test.
- **Engine:** bound to 127.0.0.1 only.
- **Child processes:** no shell and no `os.system` anywhere (test), every child process is hidden and tracked, and Windows Job Object kill-on-close is tested on Windows CI.
- **Keys:** keys stay in the OS keyring and vault and never go to logs, the DB, config or crash reports (existing redaction tests).
- **Uploads:** screenshots are decoded with Pillow and size-capped.
- **File serving:** files are served only from the media folder and your own library folders.

## Licences
**Bundled assets** (test: every file has its licence next to it):
- fonts: OFL (Montserrat, Anton, Archivo Black);
- emoji: Noto Emoji, Apache 2.0;
- SFX: original, CC0.

**Music:** only tracks in your library with a recorded licence can be rendered (existing).

**Never fetched:**
- no TikTok or Instagram media or APIs are fetched (test);
- style references are your own screenshots;
- B-roll and stickers come only from your folders.

## Soak and crash tests
`scripts/soak.py` loops through these steps on a 1080p facecam clip:
1. a random style;
2. cuts, speed, freeze, text, sticker, transition, colour and audio keys;
3. a preview still;
4. a proxy render, plus a full export every 5th round.

It fails if memory grows by more than 150 MB, handles or temp folders grow, children are left behind, or renders slow by more than 2×.
- **CI:** a 30 s run (`test_short_soak_has_no_leaks`).
- **The 6–12 h run:** this needs your PC, so it hasn't been done here:
  `python scripts\soak.py --minutes 600 --out soak.json` (from the `backend` folder's parent).
- **Crash test:**
  - jobs that were running are re-queued on restart;
  - leftover render folders are removed;
  - on Windows, killing the engine kills its ffmpeg (Job Object), tested on Windows CI;
  - unsaved Editor changes are offered back.
